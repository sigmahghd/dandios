# Виртуальный bootstrap XNU: software-alias model, не прошивка

## Рубеж

Полный экспериментальный Image входит через настоящий стартовый код, проверяет
FDT/mblock, копирует XNU и подготавливает EL2→EL1h. В новой опциональной проверке
выполняется также виртуальный путь XNU: `arm_init`, `cpu_data_init`,
`PE_init_platform`, `ml_parse_cpu_topology`, `cpu_bootstrap`,
`kernel_startup_bootstrap`, затем вход в `cpu_init`.

Системные регистры, ERET, кэши/TLB и активация MMU моделируются программно.
Это НЕ подтверждение аппаратного запуска и НЕ загруженная iOS.

## Как устроена проверка

- Все физические/виртуальные отображения создаются только по таблицам,
  которые построил сам XNU. Проверяется каждая 4-КиБ страница и точное
  соответствие единственной разрешённой RAM arena.
- Два адреса используют одну backing memory, а не расходящиеся копии.
- Учитываются EL1 read-only/PXN и родительские APTable/PXNTable ограничения.
  Это проверяемое подмножество прав, не полноценная ARM MMU модель.
- После программного включения трансляции память загрузчика, исходного
  payload, входного FDT и непокрытые страницы больше не доступны ядру.
- MMIO не отображается, фиктивные ответы устройств не выдаются.
- Изменение таблиц/TCR/TTBR/SCTLR после активации останавливает тест: статические
  alias не используются как подмена новой аппаратной трансляции.
- Неизвестный системный регистр останавливает тест, а не становится нулём.
- Без настройки CPACR FP/SIMD не разрешаются только потому, что Unicorn их умеет.

## Таймеры и CPU

CPU0 MIDR 0x410fd034 присутствовал в ранее переданном recovery dmesg.
MPIDR и 13-МГц CNTFRQ согласуются с ранее снятым Stage0-профилем. Это не
полный набор реально измеренных системных регистров и не проверка всех ядер.

В bridge добавлена явная начальная запись CNTKCTL_EL1=0: доступ EL0 к
таймерам/счётчикам и event stream не наследуются от неизвестного firmware.
XNU затем сам меняет эту политику. На устройстве этот bridge не проверен.

Проверяются два независимых сценария:

1. Без профиля счётчика: остановка на первом CNTVCT_EL0 после входа в arm_init.
2. С ЯВНО синтетическим монотонным счётчиком: начальное значение 1, шаг 13000
   тиков на чтение при частоте 13 МГц. Это не реальное время и не модель IRQ.
   Этот вариант проходит startup и останавливается в machine_read_clidr,
   вызванной из cpu_init: реальное значение CLIDR_EL1 пока неизвестно.

Никакие значения CLIDR/CCSIDR не угаданы и не подставлены ради продолжения.
Для аппаратного этапа нужны достоверные параметры кэшей и диагностика на телефоне.

## Автоматические проверки

18 отдельных тестов backing memory/alias/прав доступа и 7 полных сценариев:
без счётчика; с синтетическим счётчиком; отсутствующий MIDR; повреждённый
дескриптор; запрет виртуального исполнения; отсутствующий boot_args alias;
FP, намеренно оставленный выключенным. У проверок есть ожидаемые причины
остановки: одного «процесс не упал» недостаточно.

Прежние 22 handoff-сценария и prepare-only тесты остаются отдельными.
Отчёты ограничены по размеру, исходники не содержат дампов телефона/SDK/KDK.

## Ограничения

NOT FOR PHONE: не выполнять fastboot flash/boot с этими Image/ELF.
Предсказуемый тестовый seed, синтетическое ADT, ограниченная RAM arena,
отсутствующая модель EL3/ATF, MMIO, SMP, watchdog и доставки прерываний.
Ни загрузка аппаратного XNU, ни драйверы, ни пользовательская среда iOS
этими тестами не подтверждаются. Лимит выполнения — 2 миллиона инструкций XNU
и таймаут 120 секунд на полный сценарий.
